# 구현 계획서 - 영어 레벨 테스트 웹 애플리케이션

GitHub Pages에 배포할 수 있는 고품질의 영어 레벨 테스트 웹 애플리케이션을 제작합니다. 지루하지 않게 각 스테이지별로 5분의 제한시간을 두고, 좋은 점수를 받으면 다음 단계로 이동하는 방식의 동적 스테이지 진행 구조를 가집니다. 디자인은 다크 모드, 글래스모피즘, 부드러운 애니메이션 및 세련된 타이포그래피를 사용하여 시각적으로 프리미엄 느낌을 주도록 구현합니다.

## 사용자 검토 필요 사항

> [!IMPORTANT]
> - **깃허브 저장소 설정**: 원격 저장소 주소는 `git@github.com:tramper2/EngLevelTest.git`로 구성됩니다.
> - **GitHub Pages 배포 방식**: 이 앱은 빌드 과정이 필요 없는 순수 HTML/CSS/JavaScript SPA(싱글 페이지 애플리케이션)로 제작하여, `main` 브랜치에 코드를 푸시하면 바로 배포할 수 있도록 구성합니다. 배포를 자동화할 수 있는 PowerShell 스크립트(`deploy.ps1`)를 함께 제공합니다.
> - **스테이지 및 평가 방식**: 총 3개 스테이지(초급/Intermediate/Advanced)로 나뉘며, 각 스테이지는 5분(300초)의 타임아웃이 있습니다. 각 스테이지에서 70% 이상의 정답률을 기록해야 다음 스테이지 잠금이 해제되고 진행할 수 있습니다.
> - **영어 문장 자연스러움 검증**: 생성된 300개의 영어 문장들에 대한 문법적 적합성 및 실생활 표현 적합성 검증을 마쳤습니다. 단복수 주어-동사 매칭 오류, 전치사의 슬래시 표기법 혼동, 대명사/소유격 불일치, 그리고 관사 충돌 문제(A/An) 등 비문법적 요소를 전면 배제했습니다.
> - **토익 예상 점수 연동**: 한국 사용자에게 친숙한 인지도 지표인 토익(TOEIC) 점수 환산 데이터셋(100점~990점 범위)을 설계하여 각 스테이지 통과 전환 화면 및 수료증 화면에 동적으로 표시합니다.

## 제안된 변경 사항

`D:\Study\WebPage\EngLevelTest` 폴더에 HTML5, CSS3, JavaScript 파일을 작성합니다.

애플리케이션의 핵심 디자인 시스템을 정의합니다.

#### [NEW] [questions.js](file:///D:/Study/WebPage/EngLevelTest/questions.js)
CEFR 레벨을 기반으로 엄선한 문제 세트가 포함된 데이터 파일입니다.
- **초급 (A1-A2)**: 기본 문법, 일상 어휘, 쉬운 대화문 (100문제 풀, 시험당 10문제 무작위 출제)
- **중급 (B1-B2)**: 조동사, 완료 시제, 비즈니스 영어, 짧은 독해 (100문제 풀, 시험당 10문제 무작위 출제)
- **고급 (C1-C2)**: 미묘한 뉘앙스 차이, 고급 어휘, 문법 오류 수정, 학술/시사 독해 (100문제 풀, 시험당 10문제 무작위 출제)
- 문제 객체 구조: `id`, `text` (지문 및 문제), `options` (선택지 4개), `correctAnswer` (정답 인덱스), `explanation` (한국어 해설), `type` (문법/어휘/독해 등).

#### [NEW] [app.js](file:///D:/Study/WebPage/EngLevelTest/app.js)
애플리케이션의 동작과 상태를 관리하는 JavaScript 핵심 파일입니다.
- 상태 관리 (현재 스테이지, 현재 진행 중인 문제 번호, 정답 수, 남은 시간 타이머).
- 5분(300초) 카운트다운 타이머 동작 및 0초 도달 시 자동 제출 기능.
- 결과 계산 및 스테이지 합격/불합격 여부에 따른 화면 전환 처리.
- 테스트 진행 정보를 `localStorage`에 임시 저장하여 브라우저 새로고침 시에도 기존 레벨 진행 상태 유지.
- 최종 테스트 완료 후 레벨 등급(CEFR 등급)과 세부 성적표(어휘, 문법 등 항목별 정답률) 및 수료증(Certificate) 시각화.

## 검증 계획

### 수동 검증
1. 웹 브라우저로 `index.html`을 실행합니다.
2. 시작 화면에서 스테이지 선택이 정상 작동하는지 확인합니다.
3. 문제를 풀면서 타이머 작동 여부 및 60초 미만일 때 색상 변경 등을 확인합니다.
4. 스테이지 종료 시 70% 이상 정답일 때 다음 단계가 활성화되는지 확인합니다.
5. 반응형 디자인이 모바일 크기에서도 깨지지 않고 예쁘게 나오는지 검사합니다.
6. 배포 스크립트를 실행하여 깃허브 원격 저장소에 올리고 실제로 GitHub Pages 주소에서 정상 동작하는지 테스트합니다.
